# PoViShield

**Intelligent Linux Application Sandboxing and Security Benchmarking Platform**

PoViShield learns an application's observed system-call behavior (ptrace), generates least-privilege seccomp-bpf
policies, explains security decisions with auditable risk metrics, enforces execution boundaries under the Linux kernel,
and identifies unexpected behavior without blindly granting new permissions.

The platform provides an end-to-end workflow:
```
Terminal Command → Pre-Execution Policy Evaluation → Security Explanation →
Safety Gate Approval Check → Kernel-Enforced Execution (Seccomp-BPF / Ptrace) →
Live Telemetry & Auditable Event Timeline → Web Dashboard Synchronization
```

> **Research Prototype Status:** PoViShield is a Linux security research prototype and portfolio platform.
> Read [`docs/THREAT_MODEL.md`](docs/THREAT_MODEL.md) and [`SECURITY.md`](SECURITY.md) for documented security boundaries and limitations.

## 3. Real Terminal Integration (`povishield run`)

PoViShield features an explicit CLI supervisor (`./povishield`) that evaluates, confines, and audits execution directly from your Linux terminal:

```bash
# Permitted execution under verified least-privilege policy (Exit code 0):
./povishield run -- /usr/bin/echo "Hello from PoViShield"

# Pre-evaluate security boundaries and risk reduction before process launch:
./povishield evaluate -- /usr/bin/cat /dev/null

# Enforced Seccomp Kill Demo: unlearned syscall triggers kernel SIGSYS kill (Exit code 159 / -31):
./povishield run --profile results/profiles/echo.json -- /usr/bin/uname -a

# Safety Gate Fail-Closed Demo: unapproved commands fail closed before launch (Exit code 126):
./povishield run --mode approval-required -- /usr/bin/cat /dev/null

# Safety Gate Approved Demo: approved target executes under confinement (Exit code 0):
./povishield run --mode approval-required -- /usr/bin/grep "root" /etc/passwd

# Dynamic Ptrace Audit Mode: inspects and records live events without killing:
./povishield run --mode inspect -- /usr/bin/ls /tmp

# List recorded audit execution sessions:
./povishield list
```

### Execution Modes

| Mode | Pre-Execution Check | Enforcement Mechanism | Behavior on Unlearned Syscall |
|---|---|---|---|
| `enforce` *(default)* | Calculates attack surface reduction, risk scores, withheld critical syscalls | Linux Seccomp-BPF (`SCMP_ACT_KILL_PROCESS`, `PR_SET_NO_NEW_PRIVS`) | **Kernel Kill (`SIGSYS` / 159)** |
| `inspect` | Observes and records all syscalls via dynamic tracer | Linux Ptrace (`PTRACE_SYSCALL`) | **Audited and recorded** (Non-killing) |
| `approval-required` | Verifies candidate policy approval in `results/approvals.jsonl` | Linux Seccomp-BPF | **Fails closed (`exit 126`)** if unapproved |

## 4. Web Security Operations Console (UI & API)

PoViShield features a dark cybersecurity interface inspired by diagnostic terminal monitoring. It synchronizes terminal execution sessions, live syscall streams, policy comparisons, and evidence ledgers.

### Starting the Platform

```bash
# Terminal 1: FastAPI Backend
.venv/bin/python -m uvicorn api.main:app --host 127.0.0.1 --port 8000

# Terminal 2: React + Vite Frontend
cd frontend && npm run dev
```

Open [http://localhost:5175](http://localhost:5175) or [http://127.0.0.1:5175](http://127.0.0.1:5175) in your browser.

### Key Console Features

1. **Ambient Telemetry Background:** Lightweight animated diagnostic telemetry stream displaying kernel subsystem initialization, seccomp filters, and live event bus activity (automatically pauses on tab hide or `prefers-reduced-motion`).
2. **Terminal / Execute Console:** Interactive browser terminal connected to the backend execution supervisor. Type or select preset command vectors, preview policy decisions, execute under kernel confinement, and inspect live stdout/stderr and audit timelines.
3. **Runtime Monitor:** Live and recorded system-call event stream with category tags (`File I/O`, `Memory`, `Process`, `Network`, `Privileged`) and violation alerts.
4. **Policy Explorer & Comparator:** Diff baseline vs counterfactual policies, inspect tier classifications (`experimentally_necessary` vs `removable_for_tested_tasks`), and review withheld critical syscalls.
5. **Evidence Ledgers & Safety Gate:** Inspect append-only JSONL trial records, run independent ledger audits, and inspect safety gate approvals.

## 5. Security Architecture

| Layer | Mechanism | Security Guarantee | Source |
|---|---|---|---|
| **Supervisor** | `analysis/runner.py`, `./povishield` | Safe argument parsing, pre-execution evaluation, session timeline logging | `analysis/runner.py` |
| **Learner** | `ptrace` (PTRACE_SYSCALL) | Traverses fork/clone/exec, logs events to JSONL, atomic profile generation | `src/tracer/learn.c` |
| **Ablation** | Leave-one-out minimization | Empirically proves permissions unnecessary under `SCMP_ACT_KILL_PROCESS` | `analysis/ablate.py` |
| **Evidence Ledger** | Append-only JSONL | SHA-256 trial hashes, reproduce commands, fail-closed verification | `analysis/ledger.py`, `analysis/audit_ledger.py` |
| **Safety Gate** | Pre-enforcement verification | Regression testing, adversarial containment, fail-closed approval gate | `analysis/verify.py` |
| **Enforcement** | libseccomp BPF filter | Strict allowlist, `PR_SET_NO_NEW_PRIVS`, kernel SIGSYS termination on violation | `src/policy/seccomp_gen.c` |
| **Container Sandbox** | Namespaces + cgroup v2 | PID/mount/UTS/IPC/net isolation, `pivot_root`, resource caps (needs root) | `src/runtime/sandbox.c` |
| **Local API** | FastAPI + Uvicorn | DNS rebinding protection (Host header check), CORS loopback validation, input allowlisting | `api/main.py` |

## 6. Threat Model & Limitations

- **Empirical Coverage:** A profile covers only observed or counterfactually verified behavior. It cannot predict untested execution paths.
- **Syscall Arguments:** Standard Seccomp filters validate syscall numbers and scalar arguments; pointer targets in user memory are subject to TOCTOU unless inspected by specialized tracers.
- **Host Security:** Seccomp restricts system calls from the target process; it does not replace kernel isolation or mitigate unpatched kernel vulnerabilities.
- **Learn Mode Safety:** Dynamic tracing via ptrace should only be conducted on trusted binaries during policy generation.

For full architectural details, formal assurance properties, and responsible disclosure policies, see [`docs/THREAT_MODEL.md`](docs/THREAT_MODEL.md), [`docs/SECURITY_ASSURANCE.md`](docs/SECURITY_ASSURANCE.md), and [`SECURITY.md`](SECURITY.md).

## 7. Multi-Device Fleet Security & Remote Linux Agent

PoViShield can be deployed as a multi-device Linux fleet security platform. A user can open the central dashboard from any computer, pair remote Linux machines via single-use cryptographically bound pairing codes, inspect kernel security capabilities, dispatch policy-monitored commands, and revoke authorizations in real time.

```
Central Control Plane (FastAPI + React Dashboard)
    ▲                ▲
    │ HTTPS (poll)   │ HTTPS (poll)
    ▼                ▼
Remote Device 1   Remote Device 2 (Outbound-only pull loop, zero open inbound ports)
```

### Key Security & Privacy Guarantees

- **Outbound-Only Pull Architecture:** The local Linux agent (`agent/povishield_agent.py`) connects outbound to the control server over HTTPS. It never listens on open public ports, preventing port scanning and arbitrary incoming network attacks.
- **Short-Lived, Single-Use Pairing:** Pairing codes expire after 10 minutes and can only be consumed once. Each pairing attempt is rate-limited (5/min per IP/user) to prevent brute-force exploitation.
- **Strict User Ownership Isolation:** Devices, tasks, and telemetry are isolated per authenticated user (`X-PoViShield-User` / bearer auth). One user cannot inspect or control another user's fleet.
- **Truthful Capability Probing:** The agent directly queries the Linux kernel (`/proc/self/status` for seccomp, `prctl(PR_SET_NO_NEW_PRIVS)`, cgroups v2, user namespaces). It never claims enforcement is active if unsupported by the host.
- **Fail-Closed Seccomp Confinement:** Commands executed under `enforce` mode are confined by libseccomp filters. Unauthorized syscalls result in immediate kernel `SIGSYS` termination (exit code 159 / -31).
- **Privacy by Default:** By default, command stdout and stderr are kept local or redacted unless explicit output-sharing is authorized.
- **Instant Revocation & Cleanup:** Revoking a device instantly invalidates its bearer token, terminates or rejects pending tasks, and halts telemetry reporting.

### Device Pairing & Installation Flow

#### Option A: One-Liner Web Installer
On the target Linux machine, open a terminal and run the one-liner provided by the connection wizard:
```bash
curl -sSL https://<server-domain>/install.sh | bash -s -- --server https://<server-domain> --code <PAIRING-CODE>
```

#### Option B: PoViShield Local CLI
If the repository or CLI is already present on the target host:
```bash
# 1. Probe local kernel security capabilities truthfully
./povishield agent probe

# 2. Pair with the central control plane
./povishield agent pair --server https://<server-domain> --code <PAIRING-CODE>

# 3. Start the outbound heartbeat supervisor loop
./povishield agent start
```

### Production Deployment Notes

1. **Central API:** Deploy FastAPI with Uvicorn behind a TLS reverse proxy (Nginx, Caddy, or Cloudflare) with standard HTTPS certificates. Set environment variables:
   - `POVISHIELD_DATABASE_URL`: Path to persistent SQLite DB (`results/povishield.db`) or PostgreSQL connection string.
   - `POVISHIELD_CORS_ORIGINS`: Comma-separated list of allowed frontend domains.
2. **Dashboard UI:** The React console can be compiled statically via `cd frontend && npm run build` and hosted on any static web host, CDN, or reverse-proxied by Nginx.
3. **Container Security Caveat:** If deploying the agent or runner inside Docker/Kubernetes containers, ensure the container runtime allows seccomp filters (`--security-opt seccomp=unconfined` or custom profiles permitting `PR_SET_NO_NEW_PRIVS` and `SCMP_ACT_KILL_PROCESS`). Standard unprivileged cloud containers with default Docker seccomp profiles may block nested seccomp initialization.
